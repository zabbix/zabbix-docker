What is Zabbix?

Zabbix is an enterprise-class open source distributed monitoring solution.

Zabbix monitors numerous parameters of a network and the health and integrity of servers. It provides flexible notification, reporting and data visualisation features.

For more information and related downloads for Zabbix components, please visit https://hub.docker.com/u/zabbix/ and https://www.zabbix.com/.

What is Zabbix Bridge Adapter?

Zabbix Bridge Adapter connects a Zabbix installation to Zabbix Bridge for use with the Zabbix mobile application.

Zabbix Bridge Adapter images

These are the official Red Hat UBI-based Zabbix Bridge Adapter container images. Images are updated when new releases are published.

How to use this image

Before starting zabbix-bridge-adapter

Zabbix server and the Zabbix frontend must be available. Obtain the Server ID from Reports > System information in the target Zabbix frontend.

The examples use an existing Podman network named zabbix-backend, shared with Zabbix server. The network must provide access to the Zabbix API and Zabbix Bridge.

Reading and accepting the EULA

Read the bundled Zabbix Mobile App End User License Agreement (EULA) before accepting it:

$ podman run --rm zabbix/zabbix-bridge-adapter-trunk:tag zabbix_bridge_adapter license show | less

Here and below, tag specifies the image version. Use the same image version for license acceptance and service startup.

If you agree to the terms, create bridge-adapter.env with the EULA version shown by the command and the values for your installation:

ZBX_EULAVERSION=<reviewed EULA version>
ZBX_SERVERID=<Server ID from the Zabbix frontend>
ZBX_ZABBIXAPIURL=http://zabbix-web-nginx:8080/api_jsonrpc.php
ZBX_ZABBIXAPITLSCONNECT=disabled

For an HTTPS API URL, configure the TLS variables described below. Configure ZBX_ALLOWEDAPIMETHODS_<N> in the same file to allow the API methods required by the mobile application.

Accept the EULA using a persistent data volume:

$ podman run --rm --network none --read-only \
    --env-file bridge-adapter.env \
    --volume zabbix-bridge-adapter-data:/var/lib/zabbix/bridge-adapter \
    zabbix/zabbix-bridge-adapter-trunk:tag accept-license

This command records acceptance of the specified EULA version and exits. Review and accept the terms again if the bundled EULA changes.

Start zabbix-bridge-adapter

Start a Zabbix Bridge Adapter container using the same environment file and data volume:

$ podman run --name some-zabbix-bridge-adapter \
    --network zabbix-backend \
    --read-only --tmpfs /tmp \
    --tmpfs /var/lib/zabbix/enc_internal:mode=0700,uid=1997,gid=0 \
    --env-file bridge-adapter.env \
    --volume zabbix-bridge-adapter-data:/var/lib/zabbix/bridge-adapter \
    -d zabbix/zabbix-bridge-adapter-trunk:tag

Where some-zabbix-bridge-adapter is the name you want to assign to your container and tag specifies the image version.

Connects from Zabbix server in other containers

Connect Zabbix server to the same network and set its ZBX_BRIDGEADAPTERURL variable to:

http://some-zabbix-bridge-adapter:10054/rpc

Use an HTTPS URL when TLS is enabled on the Adapter listener.

Container shell access and viewing Zabbix Bridge Adapter logs

Start a shell inside the container as follows:

$ podman exec -ti some-zabbix-bridge-adapter /bin/bash

View the container log as follows:

$ podman logs some-zabbix-bridge-adapter

Environment Variables

When you start the zabbix-bridge-adapter image, you can adjust the configuration by passing environment variables on the podman run command line or using --env-file.

ZBX_EULAVERSION

Exact version of the reviewed EULA to accept. The value must match the version displayed by zabbix_bridge_adapter license show. The variable is used only by the EULA acceptance step; setting it does not accept the EULA during normal Adapter startup. Native license commands can be run with --entrypoint /usr/sbin/zabbix_bridge_adapter.

ZBX_SERVERID

Full Server ID displayed under Reports > System information in the target Zabbix frontend. This variable is required.

ZBX_ZABBIXAPIURL

URL of the target Zabbix JSON-RPC API endpoint, for example https://zabbix.example.com/api_jsonrpc.php. This variable is required.

ZBX_ZABBIXBRIDGEURL

URL used to retrieve the Zabbix Bridge configuration. The default value is https://config.mobilebridge.zabbix.com/.well-known/bridge-configuration.

ZBX_ZABBIXAPITLSCONNECT

TLS mode used for outbound connections to the Zabbix API. Supported values are:

  • disabled - use plain HTTP;
  • required - use HTTPS without certificate verification;
  • verify_ca - use HTTPS and verify the certificate issuer;
  • verify_full - use HTTPS and verify the certificate issuer and hostname.

Use disabled for an HTTP API URL. The default is required for HTTPS.

ZBX_ZABBIXAPITLSCAFILE, ZBX_ZABBIXAPITLSCA

ZBX_ZABBIXAPITLSCAFILE specifies the CA file used to verify the Zabbix API certificate. A relative path is resolved against /var/lib/zabbix/enc. Alternatively, ZBX_ZABBIXAPITLSCA provides the CA certificate content directly. A CA is required when ZBX_ZABBIXAPITLSCONNECT is set to verify_ca or verify_full.

ZBX_LISTENIP

IP address or hostname on which the Adapter accepts requests from Zabbix server. By default, all available addresses are used.

ZBX_LISTENPORT

Port on which the Adapter accepts requests from Zabbix server. The default value is 10054. The RPC endpoint is available at /rpc.

ZBX_LISTENHEALTHPORT

Port exposing the /health and /ready endpoints. The default value is 8081. The container health check uses /ready; the container becomes healthy when the Adapter is ready to handle requests.

ZBX_DEBUGLEVEL

Debug level from 0 to 5. The default value is 3.

ZBX_ALLOWEDAPIMETHODS_<N>

Zabbix API methods that the Adapter is allowed to call. Specify each method in a separate variable, using consecutive indexes starting with 0. Each entry is either an exact method name, resource.* or *.method:

ZBX_ALLOWEDAPIMETHODS_0=apiinfo.version
ZBX_ALLOWEDAPIMETHODS_1=host.get

If no variables are specified, the default deny-all policy applies and the Zabbix mobile application cannot use the Adapter. The minimal set of methods the mobile application currently needs is:

ZBX_ALLOWEDAPIMETHODS_0=apiinfo.version
ZBX_ALLOWEDAPIMETHODS_1=device.onboard
ZBX_ALLOWEDAPIMETHODS_2=device.offboard
ZBX_ALLOWEDAPIMETHODS_3=user.get
ZBX_ALLOWEDAPIMETHODS_4=role.get
ZBX_ALLOWEDAPIMETHODS_5=problem.get
ZBX_ALLOWEDAPIMETHODS_6=event.get
ZBX_ALLOWEDAPIMETHODS_7=event.acknowledge
ZBX_ALLOWEDAPIMETHODS_8=trigger.get
ZBX_ALLOWEDAPIMETHODS_9=alert.get
ZBX_ALLOWEDAPIMETHODS_10=host.get
ZBX_ALLOWEDAPIMETHODS_11=hostgroup.get

Listener TLS variables

ZBX_TLSMODE=none
ZBX_TLSCAFILE=
ZBX_TLSCA=
ZBX_TLSCERTFILE=
ZBX_TLSCERT=
ZBX_TLSKEYFILE=
ZBX_TLSKEY=
ZBX_TLSALLOWEDCN=

The default none mode accepts unencrypted connections. For production deployments, mutual TLS (mtls) is recommended for the server-facing listener. Set ZBX_TLSMODE to tls for TLS or mtls for mutual TLS. Certificate, private key and CA file names are specified using the ZBX_TLSCERTFILE, ZBX_TLSKEYFILE and ZBX_TLSCAFILE variables. Relative paths are resolved against /var/lib/zabbix/enc. Alternatively, the certificate, private key and CA contents can be passed directly using ZBX_TLSCERT, ZBX_TLSKEY and ZBX_TLSCA. ZBX_TLSALLOWEDCN is a comma-separated list of permitted client certificate Common Names in mTLS mode.

Allowed volumes for the Zabbix Bridge Adapter container

/var/lib/zabbix/bridge-adapter

The volume stores persistent Adapter data and EULA acceptance. Use the same writable volume for license acceptance and service startup. For a bind mount, create the directory beforehand and grant access to UID 1997. Run both containers with the same UID.

/var/lib/zabbix/enc

The volume stores TLS files referenced by the ZBX_TLSCAFILE, ZBX_TLSCERTFILE, ZBX_TLSKEYFILE and ZBX_ZABBIXAPITLSCAFILE variables. Relative paths are resolved against this directory. TLS material provided inline is written to /var/lib/zabbix/enc_internal; mount that directory as writable tmpfs when the container root filesystem is read-only.

/var/lib/zabbix/ssl/certs, /var/lib/zabbix/ssl/keys and /var/lib/zabbix/ssl/ssl_ca

These volumes provide listener certificates, private keys and CA certificates. Mount them read-only.
